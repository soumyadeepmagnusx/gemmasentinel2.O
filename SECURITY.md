# Security Policy

| :------ | :----------------- |
| 1.2.x   | :white_check_mark: |
| 1.1.x   | :white_check_mark: |

| < 1.0   | :x:                |

---

## 🚨 Reporting a Vulnerability

The GemmaSentinel maintainers take the security of our open-weight model harnesses, database query parsers, and AST analysis engines very seriously.

If you discover a security vulnerability or exploit vector (e.g., prompt injection leading to bypass, insecure deserialization, or unhandled AST edge cases), please report it responsibly:

1. **Do NOT open a public GitHub issue** with sensitive exploit details.
2. Submit your report using our [Security Vulnerability Report Template](.github/ISSUE_TEMPLATE/vulnerability_report.yml) or open a private [GitHub Security Advisory](https://github.com/soumyadeepmagnusx/gemmasentinel2.O/security/advisories/new).
3. Include the following information in your report:
   - Detailed description of the vulnerability.
   - Proof-of-concept (PoC) code or sample inputs.
   - Potential impact and estimated CVSS v3.1 score.
   - Any suggested mitigations or patches.

---

## ⏱️ Response Timelines

- **Initial Response:** Within 48 hours of report submission.
- **Triage & Status Update:** Within 5 business days.
- **Patch Release:** High & Critical severity issues are patched with high priority.

---

## 🏆 Bug Bounty & Acknowledgements

Responsible security researchers who discover and report valid security vulnerabilities in accordance with this policy will be credited in our release notes and Hall of Fame!
